API

The CLI is a thin client. Everything it does is an HTTP endpoint with a bearer token — useful for CI, scripts and your own tooling.

Base URL and authentication

All endpoints live under https://<dashboard-host>/api/v1. The dashboard host is the one you configured with --dashboard-origin; project hosts do not expose the API.

Protected endpoints require a personal API token in a bearer header:

bash
curl -fsS https://dok.example.com/api/v1/whoami \
  -H "Authorization: Bearer $DOK_TOKEN"

Create a token in Account → API tokens or with dok tokens create. The secret is shown once. A token acts as its user, so authorization follows team membership and role: viewers can read, members can deploy, admins and owners can change settings.

Two public endpoints

GET /api/v1/health is public. POST /api/v1/hooks/github/<app> is authenticated by an HMAC signature, not a bearer token. Everything else in this page requires a token.

Errors and limits

Errors are plain text (or a JSON {"error": "..."} object for deploy failures) with a matching HTTP status. Cross-team resources return 404 rather than 403 so their existence is not disclosed.

API status codes
StatusWhen
400Invalid name, host, env, role or JSON body.
401Missing, invalid, revoked or unbound token.
403Role is insufficient, or you cannot grant that role.
404No such project, deploy, team or certificate owner.
409Domain conflict, reserved host, last owner, or renewal owned by an external proxy.
413Upload exceeds 200 MB.
422Archive rejected (unsafe path, too many entries, too large uncompressed).
429Rate limit: 600 requests/min or 20 deploys/min per user.
507Less than 1 GB free for an upload.

Deploy an archive

The upload is a raw gzipped tar body, not multipart. The CLI does exactly this after packing:

bash
tar -czf app.tar.gz --exclude=.git --exclude=node_modules .
curl -fsS -X POST "https://dok.example.com/api/v1/projects/my-app/deploy?env=production" \
  -H "Authorization: Bearer $DOK_TOKEN" \
  -H "Content-Type: application/gzip" \
  --data-binary @app.tar.gz

A successful response looks like:

json
{
  "app": "my-app",
  "deploy_id": "4f2c9a1b8e70",
  "env": "production",
  "kind": "docker",
  "url": "https://my-app.apps.example.com",
  "host_port": 49152
}
  • env is production or preview; the X-Dok-Env header also works.
  • port sets the container port; domain sets the primary domain in the same request.
  • The first upload to a new name creates the project in your first writable team. Create it first with POST /projects if you need a specific team.
  • Uploads are streamed and capped at 200 MB. A deploy can take minutes; the request stays open until the build finishes.

For clients that cannot put the project in the path, use the root endpoint:

bash
curl -fsS -X POST https://dok.example.com/api/v1/deploy \
  -H "Authorization: Bearer $DOK_TOKEN" \
  -H "X-Dok-Project: my-app" \
  -H "X-Dok-Env: production" \
  -H "Content-Type: application/gzip" \
  --data-binary @app.tar.gz

Projects and deployments

bash
curl -fsS -X POST https://dok.example.com/api/v1/projects \
  -H "Authorization: Bearer $DOK_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"my-app","team":"acme"}'

curl -fsS https://dok.example.com/api/v1/projects/my-app \
  -H "Authorization: Bearer $DOK_TOKEN"

curl -fsS "https://dok.example.com/api/v1/projects/my-app/deployments?env=production" \
  -H "Authorization: Bearer $DOK_TOKEN"

Project JSON includes name, team_id, kind, status, domain, repo, framework, resource limits and a computed url. Deploy JSON includes the id, environment, status, commit metadata, timestamps and public URL.

bash
curl -fsS -X POST https://dok.example.com/api/v1/projects/my-app/promote/4f2c9a1b \
  -H "Authorization: Bearer $DOK_TOKEN"

Use promote for a preview or an older production build; rollback is the same operation. The deploy must be ok and its build tree must still exist.

Environment variables

Send a flat object of strings, or objects with value and secret. Add "replace": true to delete keys that are not in the request.

bash
curl -fsS -X PUT https://dok.example.com/api/v1/projects/my-app/env/production \
  -H "Authorization: Bearer $DOK_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"API_URL":"https://api.example.com","STRIPE_KEY":{"value":"sk_live_...","secret":true}}'
json
{
  "env": {
    "API_URL": "https://api.example.com",
    "STRIPE_KEY": "***"
  },
  "resolved": {
    "API_URL": "https://api.example.com",
    "STRIPE_KEY": "***"
  },
  "values_visible": true,
  "secrets_masked": true
}
  • Secrets are write-only: after saving, every read returns ***, for every role.
  • Viewers see masked values and values_visible: false.
  • resolved merges production, preview and development for the requested scope. Secret values are not inherited into preview.
  • An empty string keeps the stored value rather than erasing it.

Domains

bash
curl -fsS https://dok.example.com/api/v1/projects/my-app/domains \
  -H "Authorization: Bearer $DOK_TOKEN"

curl -fsS -X POST https://dok.example.com/api/v1/projects/my-app/domains \
  -H "Authorization: Bearer $DOK_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"domain":"app.example.com"}'

curl -fsS -X DELETE https://dok.example.com/api/v1/projects/my-app/domains/app.example.com \
  -H "Authorization: Bearer $DOK_TOKEN"

The legacy endpoint POST /api/v1/apps/{app}/domain sets the project's primary domain, mirroring dok domain. The /projects/{app}/domains collection adds extra domains without replacing the default host. Reserved hosts and domains owned by another project return 409.

Proxy settings

bash
curl -fsS https://dok.example.com/api/v1/projects/my-app/proxy \
  -H "Authorization: Bearer $DOK_TOKEN"

curl -fsS -X PUT https://dok.example.com/api/v1/projects/my-app/proxy \
  -H "Authorization: Bearer $DOK_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "headers": [["X-Frame-Options", "DENY"]],
    "basic_auth_user": "acme",
    "basic_auth_password": "correct horse",
    "redirect": "www-to-apex",
    "compression": true,
    "force_https": true,
    "max_body_mb": 32
  }'

GET returns basic_auth_configured and a null basic_auth_hash; the password is never returned. PUT accepts basic_auth_password to set a new argon2 hash. Headers are limited to 20; reserved hop-by-hop headers are rejected.

Logs, metrics and access logs

bash
curl -fsS "https://dok.example.com/api/v1/projects/my-app/logs?env=production" \
  -H "Authorization: Bearer $DOK_TOKEN"

curl -fsS -N "https://dok.example.com/api/v1/projects/my-app/logs/stream?env=production" \
  -H "Authorization: Bearer $DOK_TOKEN"

curl -fsS https://dok.example.com/api/v1/projects/my-app/metrics \
  -H "Authorization: Bearer $DOK_TOKEN"

curl -fsS "https://dok.example.com/api/v1/projects/my-app/access-log?limit=100&status_min=500" \
  -H "Authorization: Bearer $DOK_TOKEN"
  • logs returns JSON with build, runtime, env and the selected deploy.
  • logs/stream returns text/plain and stays open. Static projects return “no container (static app)”. Docker-unavailable returns 503.
  • metrics includes deploy counts, latest deploy, container stats and one-hour traffic (requests, 5xx, p95).
  • access-log supports limit (max 500), status_min and since (Unix seconds).

Teams, members and invites

bash
curl -fsS https://dok.example.com/api/v1/teams \
  -H "Authorization: Bearer $DOK_TOKEN"

curl -fsS -X POST https://dok.example.com/api/v1/teams/acme/invites \
  -H "Authorization: Bearer $DOK_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"role":"member"}'

curl -fsS -X PUT https://dok.example.com/api/v1/teams/acme/members/sam \
  -H "Authorization: Bearer $DOK_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"role":"admin"}'

Invite creation returns {"token","link","role"}; the link is single-use and expires in seven days. Only owners may grant admin or owner; admins may invite member and viewer. Removing the last owner returns 409.

Tokens

bash
curl -fsS -X POST https://dok.example.com/api/v1/tokens \
  -H "Authorization: Bearer $DOK_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"ci"}'

# → {"token":"dok_...","name":"ci","login":"dok login https://... dok_..."}

curl -fsS -X DELETE https://dok.example.com/api/v1/tokens/4f2c9a1b8e70 \
  -H "Authorization: Bearer $DOK_TOKEN"

The secret is printed once and stored as a hash. GET /tokens returns ids, names and creation times. A token can only be revoked by its owner.

GitHub webhook

The hook is not bearer-authenticated. It verifies X-Hub-Signature-256: sha256=<hmac> over the raw request body using the project secret, then checks the branch.

bash
curl -fsS -X PUT https://dok.example.com/api/v1/projects/my-app/webhook \
  -H "Authorization: Bearer $DOK_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"secret":"<random>","branch":"main"}'

curl -fsS https://dok.example.com/api/v1/projects/my-app/webhook \
  -H "Authorization: Bearer $DOK_TOKEN"

Point the GitHub webhook at POST /api/v1/hooks/github/my-app. Pushes outside the configured branch are ignored; a valid push records the commit SHA, message and author on the deploy.

Certificates

bash
curl -fsS https://dok.example.com/api/v1/certificates \
  -H "Authorization: Bearer $DOK_TOKEN"

curl -fsS -X POST https://dok.example.com/api/v1/certificates/app.example.com/renew \
  -H "Authorization: Bearer $DOK_TOKEN"

Renewal forces a fresh ACME order and is only available in built-in edge mode. When Traefik or Caddy owns TLS, the endpoint returns 409 telling you renewal belongs to the external proxy.

Health

bash
curl -fsS https://dok.example.com/api/v1/health
# → {"ok":true,"version":"2.0.0"}

Health is public and safe for uptime checks. It proves the process is answering; it does not check Docker, disk space or certificates.

Legacy aliases

The original /api/v1/apps/... routes are kept as aliases for older clients: list, get, delete, deploy, logs, deployments, promote, rollback, env, domain, repo, git-init and redeploy. New clients should use /api/v1/projects/.... The two sets share the same handlers and authorization.
