Troubleshooting

Start with the symptom, not the stack. Each section names the check that confirms the cause and the command that fixes it.

First checks

Most failures are visible in three places: the service log, the deploy log and DNS. Run these before changing anything:

bash
systemctl --user status dok --no-pager
journalctl --user -u dok -n 100 --no-pager
dok whoami
dok logs my-app
dok certs list
dig +short my-app.example.com

502 Bad gateway

A 502 means dok reached the route but the project behind it did not answer. The branded error page names the project and the last successful production deploy, and includes an x-request-id you can match in the access log.

  1. Did the container exit? dok logs my-app shows build and runtime output. dok deploys my-app shows whether the last deploy is ok or failed.
  2. Is it listening on the right port? The port order is --port, dok.toml, Dockerfile EXPOSE, then 3000. If the app listens on 8080, set it explicitly: dok push . --app my-app --port 8080.
  3. Is it bound to 0.0.0.0? A process inside the container that binds 127.0.0.1 is unreachable from Docker's published port. Bind all interfaces.
  4. Did it crash after starting? A missing env var or a database migration at boot is common. Check the runtime log, set the variable, then redeploy or roll back.
bash
dok logs my-app
dok deploys my-app
dok rollback my-app 4f2c9a1b
dok access-log my-app --limit 20

Static projects do not have a container, so a missing file is a branded 404 rather than a 502. If a static project appears broken, check dok deploys and push again.

Certificate pending or not issued

In edge mode, dok adds the host and starts the certificate path immediately. “Pending” means the ACME order has not completed, not that dok is still checking DNS.

  1. Does the hostname resolve to the machine that terminates TLS? dig +short host. Remove stale AAAA records.
  2. Are ports 80 and 443 reachable? HTTP-01 uses 80, TLS-ALPN-01 uses 443. A cloud firewall or security group is a common blocker.
  3. Is another proxy in front? In edge mode, dok must own 80/443. If Traefik owns them, dok is in external-proxy mode and dok certs renew will return a conflict.
  4. Is there a CAA record forbidding Let's Encrypt? dig CAA example.com.
  5. Did you use --acme-staging? Staging certificates are untrusted by browsers. Restart without it and renew.
bash
dok certs list
dok certs renew my-app.example.com
curl -I http://my-app.example.com/.well-known/acme-challenge/test

Let's Encrypt rate limits apply. If you have forced several renewals, wait before trying again. The full DNS table is in Domains & TLS.

DNS mismatch

“The domain works on my machine but not on my phone” is almost always DNS or IPv6:

bash
dig +short my-app.example.com A
dig +short my-app.example.com AAAA
dig +short my-app.example.com CNAME
dig @1.1.1.1 +short my-app.example.com
dig NS example.com
  • The A answer must be the server's public IPv4. An old address survives until its TTL expires.
  • An AAAA record pointing at a host without IPv6 breaks clients that prefer IPv6. Delete it or fix it.
  • A CNAME must point at the dok host, not at an app hostname. CNAMEs at the zone apex are usually invalid; use an A record there.
  • If a CDN proxy is enabled, set the record to DNS-only while issuing a certificate. TLS-ALPN-01 cannot pass through a terminating proxy.

Deploy rejected

A rejected upload never reaches the build. The message tells you which limit was hit:

Upload and build rejections
Message / statusCauseFix
“unknown project type”No Dockerfile, manifest or index.html.Add one, or set framework = "static" in dok.toml.
413 / “upload exceeds 200 MB”Compressed archive too large.Remove build output and assets that are regenerated; push the source, not node_modules or dist.
422 / “archive rejected”Unsafe path, symlink, too many entries, or over 500 MB uncompressed.Remove symlinks and nested archives; check the build output size.
507 / “not enough free disk space”Less than 1 GB free on the data filesystem.Free space or move --data to a larger volume.
Build failedThe Dockerfile or detected build returned non-zero.dok logs my-app; reproduce the same command locally.

A package.json with neither a start nor a build script is only accepted when an index.html exists. Otherwise add a script, a Dockerfile, or a static entry point.

401 Unauthorized

The API returns 401 for a missing, invalid, revoked or unbound token. The message distinguishes them:

  • missing token — the Authorization: Bearer header was not sent.
  • invalid token — the secret is wrong or was revoked.
  • token is not bound to a user; finish dashboard setup or issue a new token — the token predates the first user. Finish setup, then mint a new token.
bash
dok whoami
dok login https://dok.example.com
dok tokens list
dok tokens create --name laptop

If CI fails but your laptop works, check that DOK_SERVER and DOK_TOKEN point at the same instance. A token is only valid on the server that issued it; there is no central auth service.

Disk space

The server refuses an upload below 1 GB free, but builds, images and backups can fill a disk before that. Inspect before deleting:

bash
df -h
du -sh ~/.local/share/dok/* | sort -h
docker system df
ls -lh ~/.local/share/dok/backups

Old build trees and the previous image tag are cleaned on the next successful deploy; the last ten per environment are retained deliberately. If you need space immediately, roll back to a known-good deploy, remove unused preview artifacts from the dashboard, and move the data directory to a larger volume. Do not delete dok.db, backups/ or acme/ to make room.

Docker missing or permission denied

Static sites do not need Docker. Container builds do. Check both the client and the socket:

bash
docker version
sudo systemctl status docker --no-pager
ls -l /var/run/docker.sock
systemctl --user restart dok

If docker version works as your user but deploys fail, the user service may have started before the group or ACL was applied. Add the user to the docker group, re-login, or use the ACL drop-in described in Self-hosting, then restart the service.

Do not expose the socket

Access to /var/run/docker.sock is effectively root on the host. Keep it local to the machine and never publish it on a TCP port.

Passkeys and the dashboard

  • “not configured” — start dok with --dashboard-origin set to a hostname WebAuthn can use, for example http://localhost:8080 or https://dok.example.com. Bare IPs fall back to localhost.
  • Origin error during registration — open the dashboard on the exact host in --dashboard-origin. Use localhost, not 127.0.0.1, for a local instance.
  • Passkey lost — register a second passkey from Account settings while you still have access. There is no password reset.
  • Wrong host after a domain change — update --dashboard-origin, restart, and open the new URL. Existing sessions are host-scoped cookies.

Preview URL 404s

Previews use <app>-<deploy8>.<base-domain>. That host needs DNS coverage: a wildcard *.apps.example.com A record is the easy option. In edge mode each preview host is added to the certificate set individually; dok does not issue wildcard certificates.

bash
dok deploys my-app
dok logs my-app --env preview
dig +short my-app-4f2c9a1b.apps.example.com

If the deploy is still running, the URL is not routable yet. If production is fine but the preview 404s, check that the push actually used --env preview and that the host appears in dok certs list (edge mode). Promote a preview with dok promote my-app <deploy-id>.

Other common failures

Short fixes
SymptomFix
Address already in useAnother dok or proxy owns the port. Change --http-port or stop the old process.
Dashboard works, apps 404The app host does not match the project domain. Check dok domains list and --base-domain.
App sees the wrong client IPAdd the proxy CIDR to --trusted-proxy; only loopback is trusted by default.
Webhook returns 401Secret mismatch or a proxy rewrote the body. The HMAC is over the raw body bytes.
Webhook returns 200 but nothing deploysThe push branch is outside the configured branch, or the repo URL is not set.
Service dies after logoutRun loginctl enable-linger "$USER", or use a system unit instead of a user unit.
