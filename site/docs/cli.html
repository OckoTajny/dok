Every command in the 2.0 CLI, grouped the way you use them. Run dok --help or dok <command> --help for the same information on your machine.

Global options

--json prints the raw API response instead of the human table. It works before or after the subcommand: dok --json apps. Commands exit non-zero on a failed request and print the server's error text.

Global options and configuration

dok login saves the server URL and token to ~/.config/dok/config.toml with mode 0600. Two environment variables override the file, which is how CI usually runs:

bash
export DOK_SERVER="https://dok.example.com"
export DOK_TOKEN="$(cat /run/secrets/dok-token)"
dok whoami
  • DOK_SERVER — base URL, for example https://dok.example.com.
  • DOK_TOKEN — API token. Prefer this or --token-file over argv.
  • --json — machine-readable output for every command.

Setup and identity

dok login <url> [token]

Verify the token against the server and save it. With no token argument, dok reads DOK_TOKEN; with --token-file, it reads the first line of a file.

bash
dok login https://dok.example.com
dok login https://dok.example.com --token-file ~/.config/dok/token

dok whoami

Show the user and teams behind the saved token. Use it after rotating a token or when a request starts returning 401.

bash
dok whoami

dok tokens list | create | revoke

Manage personal API tokens. create prints the secret once; the server stores only a hash. revoke takes the id/hash shown by list.

bash
dok tokens list
dok tokens create --name laptop
dok tokens revoke 4f2c9a1b8e70
  • --name N — label for create; defaults to cli.

Deploy and operate

dok push [dir]

Pack a directory, upload it, build on the server and deploy. Defaults to the current directory. The app name comes from dok.toml, then the directory name, then --app.

bash
dok push ./my-app --app my-app
dok push . --env preview
dok push . --domain app.example.com --port 8080
  • --app N — project name. Lowercase letters, digits and hyphens, up to 63 characters.
  • --domain H — set the project's primary domain in the same request.
  • --port P — container port; otherwise dok.toml, Dockerfile EXPOSE, then 3000.
  • --env production|preview — defaults to production.

The CLI never packs .git, node_modules, target, .venv, __pycache__, dotfiles (except .well-known) or .env*.

dok logs <app>

Print the last build log and the runtime log for an environment. -f follows the live container stream until Ctrl-C.

bash
dok logs my-app
dok logs my-app -f
dok logs my-app --env preview --deploy 9f3c2a1b
  • -f, --follow — stream runtime output.
  • --env E — production (default), preview or development.
  • --deploy ID — select one deploy id, useful for a preview container.

dok deploys <app>

List recent deploys with id, environment, commit and status. Use the id with promote or rollback.

bash
dok deploys my-app

dok promote <app> <deploy-id>

Run an earlier successful build on production. If its image still exists it is reused; otherwise dok rebuilds the retained build tree. The deploy must have finished with status ok.

bash
dok promote my-app 4f2c9a1b

dok rollback <app> <deploy-id>

Alias for promote. Roll back by pointing production at an earlier deploy; the ten most recent builds per environment are kept, and the current production deploy is protected from cleanup.

bash
dok deploys my-app
dok rollback my-app 4f2c9a1b

dok open <app>

Print the project's public URL without opening a browser.

bash
dok open my-app

dok stats <app>

Deploy counts, domain count, current status, container CPU/memory and one-hour traffic (requests, 5xx, p95 latency).

bash
dok stats my-app

Projects, domains and git

dok apps | dok projects

List projects visible to your user. apps is an alias kept for compatibility; both print the same table.

bash
dok apps
dok --json projects

dok projects create <name> · dok projects rm <name>

Create an empty project, or delete one and stop its containers. Creation defaults to your first writable team; pass --team to choose another.

bash
dok projects create billing --team acme
dok projects rm billing
  • --team T — team slug or id for create.

dok rm <app>

Stop the container and delete the project. This is the short form of dok projects rm.

bash
dok rm old-landing-page

dok domain <app> <host>

Set the project's primary custom domain. While it is set, the default <app>.<base> host is no longer routed. To keep the default and add extras instead, use the dashboard's Domains tab or POST /api/v1/projects/{app}/domains.

bash
dok domain my-app app.example.com

dok domains list <app> · dok domains rm <app> <host>

List or remove custom domains attached to a project. Removing a host stops routing it; the certificate is left to expire unless it is re-requested elsewhere.

bash
dok domains list my-app
dok domains rm my-app old.example.com

dok git <app> <repo-url>

Set the repository used by dok redeploy and the GitHub webhook. Only public https://, ssh:// and git@host:path remotes are accepted; loopback, private, link-local and metadata addresses are refused.

bash
dok git my-app https://github.com/acme/my-app.git

dok git-init <app>

Create a bare repository on the server and print the path, an SSH remote hint and a webhook secret. A post-receive hook deploys every push.

bash
dok git-init my-app
git remote add dok /home/you/.local/share/dok/repos/my-app.git
git push dok main

For a remote SSH user, that user needs read/write access to the data directory. Details in Deploying apps.

dok redeploy <app>

Clone the configured repository and deploy the configured branch again. This is the same path used by the webhook.

bash
dok redeploy my-app

dok webhook <app>

Show the GitHub webhook settings, or rotate the secret and production branch. The endpoint verifies X-Hub-Signature-256 over the raw body and ignores pushes outside the configured branch.

bash
dok webhook my-app
dok webhook my-app --secret "$(openssl rand -hex 24)" --branch main
  • --secret S — per-project HMAC secret.
  • --branch B — branch that triggers production deploys.

Environment variables

dok env <app> KEY=VALUE ...

Set one or more variables for an environment. --secret stores values write-only: the API never returns them again, and only the owner/admin can see non-secret values. An empty value keeps the stored value; it does not erase it.

bash
dok env my-app API_URL=https://api.example.com
dok env my-app STRIPE_KEY=sk_live_... --secret
dok env my-app DEBUG=1 --env preview
  • -e, --env E — production (default), preview or development.
  • --secret — mark every value in this call as write-only.

dok env pull <app> [env]

Print variables as KEY=VALUE. Secret values are printed as ***; this is for inspection, not for exporting a full secret environment.

bash
dok env pull my-app
dok env pull my-app preview

dok env rm <app> <KEY> [env]

Remove one key. The environment defaults to production.

bash
dok env rm my-app OLD_FLAG
dok env rm my-app OLD_FLAG preview

Proxy, certificates and access logs

dok proxy show <app>

Print per-project proxy settings: headers, basic auth user, redirect mode, compression, max body and force-HTTPS.

bash
dok proxy show my-app

dok proxy set <app>

Change proxy settings. Unspecified flags keep their current values; --header replaces the whole header list when supplied.

bash
dok proxy set my-app --header "X-Frame-Options: DENY" --header "Referrer-Policy: strict-origin-when-cross-origin"
dok proxy set my-app --basic-user acme --basic-password "correct horse"
dok proxy set my-app --redirect www-to-apex --force-https
dok proxy set my-app --max-body-mb 32 --no-compression
  • --header "Name: value" — repeatable, max 20 headers.
  • --basic-user U / --basic-password P — argon2-hashed basic auth.
  • --redirect off|www-to-apex|apex-to-www.
  • --compression / --no-compression.
  • --force-https / --no-force-https.
  • --max-body-mb N — request body cap, clamped to 64 MB.

dok certs list | dok certs renew <host>

List certificates with their project owners and status, or request a fresh certificate. Renewal is only available in built-in edge mode; when an external proxy owns TLS, the API returns a conflict telling you so.

bash
dok certs list
dok certs renew app.example.com

dok access-log <app>

Show recent proxy requests: time, method, path, status, latency and client IP. The proxy keeps the last 5,000 requests per project in SQLite.

bash
dok access-log my-app
dok access-log my-app --limit 200
  • --limit N — defaults to 50; the API caps it at 500.

Teams

dok teams

List the teams your user belongs to, with your role.

bash
dok teams

dok team create <name>

Create a team. The creator becomes its owner.

bash
dok team create "Acme Studio"

dok team members <team>

List members and their roles.

bash
dok team members acme-studio

dok team invite <team>

Create a single-use invite link that expires after seven days. The default role is member; only an owner may grant admin or owner.

bash
dok team invite acme-studio --role member
  • --role R — owner, admin, member or viewer; defaults to member.

dok team invites <team> · dok team revoke <team> <token>

List unused invite links, including creator, role and expiry, or revoke one immediately.

bash
dok team invites acme-studio
dok team revoke acme-studio 8c1f0d2e

dok team role <team> <user> <role>

Change a member's role. Only owners can grant admin or owner, and the last owner cannot be demoted.

bash
dok team role acme-studio sam admin

dok team remove <team> <user>

Remove a member from the team. Their personal tokens remain valid for other teams they belong to.

bash
dok team remove acme-studio sam

Server

dok serve

Run the API, dashboard, proxy and deploy worker. Every flag also has an environment variable, which is convenient for systemd.

bash
dok serve \
  --data ~/.local/share/dok \
  --http-port 8080 \
  --base-domain apps.example.com \
  --public-host dok.example.com \
  --dashboard-origin https://dok.example.com \
  --backup-keep 7
  • --data DIR — data directory; default ~/.local/share/dok (DOK_DATA).
  • --http-port P — plain HTTP port, default 8080 (DOK_HTTP_PORT).
  • --tls-port P — HTTPS port with ACME, default 443 (DOK_TLS_PORT).
  • --base-domain D — default app hosts <app>.D (DOK_BASE_DOMAIN).
  • --public-host H — host shown in CLI output (DOK_PUBLIC_HOST).
  • --dashboard-origin URL — WebAuthn origin for the dashboard (DOK_DASHBOARD_ORIGIN).
  • --backup-keep N — daily database backups to keep, default 7; 0 disables (DOK_BACKUP_KEEP).
  • --traefik-dir DIR — write per-app Traefik routers here (DOK_TRAEFIK_DIR).
  • --token T — register an API token instead of generating one (DOK_TOKEN).
  • --acme-domain D — domain for a certificate; repeatable (DOK_ACME_DOMAIN).
  • --acme-email E — Let's Encrypt contact; repeatable (DOK_ACME_EMAIL).
  • --acme-staging — use the staging directory; certificates are untrusted (DOK_ACME_STAGING).
  • --edge — bind :80/:443, redirect HTTP to HTTPS, issue certificates (DOK_EDGE).
  • --trusted-proxy CIDR — trust X-Forwarded-Proto from an additional proxy; repeatable (DOK_TRUSTED_PROXY).

There is one hidden command, dok deploy-git, invoked by the post-receive hook. You should not need to call it directly.
