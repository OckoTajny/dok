Quickstart

One server install, one token, one push. This page ends with a public URL; it assumes a Linux host, a domain you control, and Docker if you plan to run containers.

Before you start

You need three things:

  • A Linux host with a public IPv4 address — x86_64 or arm64. A small VPS is enough for a few static sites. macOS works for a local try-out.
  • Docker if you plan to run containers. Static sites are served directly and need no Docker at all.
  • A domain you control, so browsers can reach the dashboard and apps. This guide uses dok.example.com for the dashboard and apps.example.com for deployed apps.

If you use edge mode, ports 80 and 443 must be reachable from the internet. If you already run Traefik or Caddy, keep it and put dok behind it — see Self-hosting.

No domain yet?

You can run the whole flow on your laptop with localhost. Jump to Local try-out and come back when DNS is ready.

1. Install the server

The installer downloads the matching release binary from GitHub into ~/.local/bin. If no prebuilt binary exists for your platform, it falls back to cargo install. It does not create a service for you; that is one short unit file, covered in Self-hosting.

bash
curl -fsSL https://dok.djt-group.com/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
dok --version

Before starting the server, create two DNS records pointing at the machine:

DNS for the example hostnames
NameTypeValue
dok.example.comAyour server IPv4
*.apps.example.comAyour server IPv4

Now start dok in edge mode. It binds :80 and :443, redirects HTTP to HTTPS, and issues certificates as hosts appear. The dashboard certificate is requested at startup, so give HTTPS a few seconds on the very first boot.

bash
dok serve --edge \
  --base-domain apps.example.com \
  --public-host dok.example.com \
  --dashboard-origin https://dok.example.com \
  --acme-email you@example.com
  • --edge is the built-in reverse proxy and ACME client. Without it, dok speaks plain HTTP on --http-port and expects an external proxy to terminate TLS.
  • --base-domain gives every project the default host <app>.apps.example.com.
  • --public-host is the dashboard hostname; --dashboard-origin must match the URL you open in the browser because WebAuthn checks it.
Running it for real

A foreground process dies with your SSH session. Use the systemd unit, or run it inside tmux for a quick test. dok writes its data to ~/.local/share/dok unless you pass --data. Binding ports 80/443 as a non-root user needs a capability or an external proxy — see Edge mode.

2. Claim the dashboard

Open https://dok.example.com. On first visit dok asks you to register a passkey. This creates the first user and the first team; there is no password to set and no email to verify.

  1. Register a passkey with Proton Pass, iCloud Keychain, Google Password Manager, or a hardware key.
  2. Name the first team — for a solo install, “personal” is fine.
  3. Go to Account → API tokens and create a token. It is printed once. Copy it now.

The dashboard, token API and passkey flow only answer on the dashboard host (and localhost). A random hostname gets a branded error page, never the dashboard or a list of your projects.

3. Install the CLI and log in

Run this on your laptop, not the server. The same installer works on Linux and macOS, x86_64 and arm64.

bash
curl -fsSL https://dok.djt-group.com/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"

read -rs DOK_TOKEN && export DOK_TOKEN
dok login https://dok.example.com
dok whoami

dok login reads DOK_TOKEN when the token is not passed as an argument. Using read -rs keeps it out of shell history and out of ps. The result is stored in ~/.config/dok/config.toml with mode 0600.

For CI or scripts, prefer a token file:

bash
install -m600 /dev/stdin ~/.config/dok/token <<'TOKEN'
<paste token here>
TOKEN

dok login https://dok.example.com --token-file ~/.config/dok/token
Do not pass tokens as argv

Arguments are visible to other local users through ps. Prefer DOK_TOKEN, --token-file, or the saved config. dok whoami shows the user and teams behind the current token.

4. Push your first project

Make a folder with one index.html. dok sees the file, classifies the project as static, and serves it without a container.

bash
mkdir hello-dok && cd hello-dok
cat > index.html <<'HTML'
<!doctype html>
<title>Hello from dok</title>
<h1>It works.</h1>
HTML

dok push . --app hello

The first push creates the project in your first writable team. A representative run looks like this:

text
dok push hello · production · https://dok.example.com
  /home/you/hello-dok
  Packed 1 files · 312 B · 0.0s
  Uploaded 312 B in 0.0s
  Deploying hello · building on the server
  ✓ https://hello.apps.example.com

Open it with dok open hello, or just visit the URL. The project now appears in the dashboard with its deploys, logs, env vars and domains.

To deploy a container instead, add a Dockerfile to the folder and push again. No flags change. Node, Python and Go projects are detected from their manifests; the details are in Deploying apps.

5. Attach a domain

Set the project's primary domain, or add an extra domain from the dashboard if you want to keep the default hostname. A primary domain replaces the default <app>.apps.example.com route:

bash
dok domain hello hello.example.com
dok domains check hello hello.example.com
dok domains list hello

Point DNS at the dok host — the machine that terminates TLS:

DNS records for a custom domain
TypeNameValueUse when
CNAMEhello.example.comdok.example.comThe hostname is not an apex. Preferred.
Ahello.example.comyour server IPv4Apex, or a provider that will not CNAME.

The certificate is requested automatically when the host appears. Check progress with:

bash
dig +short hello.example.com
dok certs list
dok certs renew hello.example.com

If DNS is correct and ports 80/443 reach the server, issuance usually takes seconds. A pending certificate almost always means the hostname resolves elsewhere, the ports are blocked, or a proxy in front of dok is intercepting the challenge. The full failure table is in Domains & TLS.

Local try-out

You do not need a domain to evaluate dok. WebAuthn requires a hostname rather than a bare IP, so use localhost.

bash
dok serve --dashboard-origin http://localhost:8080 --base-domain apps.localhost

Open http://localhost:8080, register a passkey, create a token, then log in from a second terminal:

bash
dok login http://localhost:8080 <token>
dok push ./hello-dok --app hello
# open http://hello.apps.localhost:8080

The CLI prints the local host without the HTTP port; append :8080 when you open it. If *.localhost does not resolve on your machine, add the hostname to /etc/hosts or use a custom domain. Static sites work without Docker; Docker must be installed and the socket accessible for container builds.
