Quickstart

From folder to URL in three steps.

01 / Quickstart

The server is installed once. After that, every release is one command — from your laptop, CI, or a git hook.

STEP 01server

Put dok on a host.

One binary, edge mode on ports 80 and 443. Point a DNS record at the machine first.

bash
curl -fsSL https://dok.djt-group.com/install.sh | sh
dok serve --edge \
  --base-domain apps.example.com \
  --public-host dok.example.com \
  --dashboard-origin https://dok.example.com \
  --acme-email you@example.com
STEP 02laptop

Connect with a token.

Register a passkey in the dashboard, create a token, then save it once on your machine.

bash
curl -fsSL https://dok.djt-group.com/install.sh | sh
read -rs DOK_TOKEN && export DOK_TOKEN
dok login https://dok.example.com
dok whoami
STEP 03any folder

Push the folder.

Static, Docker, Node, Python or Go. You get a hostname immediately; custom domains are one more command.

bash
cd ./my-app
dok push . --app my-app
# → https://my-app.apps.example.com

The model

One process between your code and the internet.

02 / Model

No control plane. No external database. No YAML wall. The same binary serves the dashboard, terminates HTTP, routes hosts and talks to Docker.

Small enough to understand on a napkin.

  • 01
    Push, build, switch.

    The CLI uploads a tar.gz. The server extracts it into a fresh build directory, builds a container or serves files, waits until the new app answers, then points the host at it.

  • 02
    State is a file.

    Projects, deploys, env vars, sessions and tokens live in SQLite. Backups are database snapshots in a directory you can copy.

  • 03
    Config is optional.

    Most apps need no config file. A dok.toml only exists to pin a port, a domain, a Dockerfile or resource limits.

Features

Small surface. Complete loop.

03 / Features

Everything needed to run a real site, and nothing that needs its own operator.

01

One-command deploys

dok push packs the directory, uploads it and deploys. Dotfiles, .env*, .git, node_modules and build caches are skipped automatically.

02

Docker when you need it

A Dockerfile wins. Otherwise dok detects static, Node, Python and Go projects and generates a small build. Unknown trees fail loudly instead of serving a blank page.

03

TLS without a sidecar

Built-in edge mode speaks ACME HTTP-01 and TLS-ALPN-01. Or run plain HTTP behind Traefik or Caddy. Certificates follow the domains in the database.

04

Previews that stay separate

--env preview gets <app>-<deploy8>.<base>, its own build and its own container. Production is untouched until you promote.

05

Rollback is a command

The last ten builds per environment are kept. Point production at an earlier one with dok rollback; the current production deploy is always protected.

06

A dashboard without passwords

Sign in with a passkey — Proton Pass, iCloud, Google or a hardware key. Sessions and CSRF tokens live in SQLite, so a restart does not log you out.

07

Teams with real roles

Owner, admin, member and viewer. Invite links are single-use and expire in seven days. Personal tokens inherit the user's team role.

08

Git when you want it

git push dok main through a bare repo and post-receive hook, or a GitHub webhook with a per-project HMAC secret and branch filter.

09

Yours to inspect

MIT licensed. One binary, one data directory, SQLite. The process sets umask 077; the data directory is 0700 and the database is 0600.

Self-hosted, not home-alone

The boring parts are already handled.

Self-hosting should not mean writing your own auth, certificate renewal and backup scripts. dok ships them in the same binary — with conservative defaults you can inspect.

  • 01
    Private files by default

    The process sets umask 077; the data directory is 0700, and the database, WAL files and backups are 0600.

  • 02
    Secrets stay write-only

    Env values can be marked secret. Viewers see key names with masked values; Docker receives a 0600 env file that is deleted after start.

  • 03
    Auth you cannot phish

    Passkey dashboard, CSRF protection, persistent sessions in SQLite, and argon2 hashes for per-project basic auth.

  • 04
    A small blast radius

    Uploads are capped at 200 MB, 20,000 entries. Dotfiles are never packed. Git remotes reject loopback, private and metadata addresses.
